4.10 Potard de teinte
=============================

**Introduction**

Dans cette lecon, vous allez construire un **Potard de teinte** — un controleur de couleur interactif qui utilise un encodeur rotatif pour regler la teinte d’un module LED circulaire WS2812.
Ce module LED WS2812 contient 12 LEDs RGB WS2812 individuellement adressables, pilotes via l’interface NeoPixel basee sur SPI du Fusion HAT+.
L’encodeur rotatif externe fournit une entree utilisateur en temps reel via les broches GPIO standard.

En tournant l’encodeur, les 12 LEDs parcourent en douceur tout le spectre de couleurs RVB.
Appuyer sur le bouton integre de l’encodeur reinitialise la teinte a la valeur de depart.

#. Lorsque le script s’execute, l’anneau du module WS2812 repond a l’encodeur rotatif :

   * Les LEDs commencent en rouge (Teinte 0°).
   * Tournez l’encodeur pour parcourir en douceur toute la roue chromatique RVB. Les couleurs transitionnent en continu (rouge → jaune → vert → bleu → violet → rouge). Le terminal affiche la teinte actuelle et les valeurs RVB.
   * Appuyez sur le bouton de l’encodeur pour reinitialiser la teinte a 0° (rouge).
   * Appuyez sur Ctrl+C pour quitter. Toutes les LEDs s’eteignent avant la fermeture du programme.

**Code**

Voici le script Python pour la simulation de feux de circulation :

.. raw:: html

   <run></run>

.. code-block:: python


   #!/usr/bin/env python3

   from fusion_hat.motor import Motor
   from fusion_hat.pin import Pin, Mode, Pull
   from fusion_hat.adc import ADC
   from time import sleep, time
   import math

   BtnPin = Pin(22, mode=Mode.IN, pull=Pull.DOWN)
   motor = Motor("M0")
   thermistor = ADC("A3")

   level = 0
   currentTemp = None
   markTemp = None

   PRINT_INTERVAL = 1.0
   _last_print = 0.0

   button_event = False  # flag: button was pressed

   def temperature(samples=5, delay=0.01):
      """Read thermistor multiple times and return averaged Celsius (float) or None."""
      vals = []
      for _ in range(samples):
         analogVal = thermistor.read()
         Vr = 3.3 * float(analogVal) / 4095.0
         if (3.3 - Vr) <= 0.1:
               return None
         Rt = 10000.0 * Vr / (3.3 - Vr)
         tempK = 1.0 / (((math.log(Rt / 10000.0)) / 3950.0) + (1.0 / (273.15 + 25.0)))
         vals.append(tempK - 273.15)
         sleep(delay)
      return sum(vals) / len(vals)

   def motor_run(lv):
      lv = max(0, min(4, lv))
      motor.power(0 if lv == 0 else lv * 25)
      return lv

   def changeLevel():
      """Button press: cycle level 0~4 and set a flag for main loop to print."""
      global level, button_event
      level = (level + 1) % 5
      button_event = True

   BtnPin.when_activated = changeLevel

   def main():
      global level, currentTemp, markTemp, _last_print, button_event

      markTemp = temperature()
      while True:
         currentTemp = temperature()
         if currentTemp is None:
               print("Sensor read failed. Please check the sensor.")
               sleep(0.5)
               continue

         # Handle button event in main loop (stable timing)
         if button_event:
               button_event = False
               markTemp = currentTemp
               print(f"[Button] Level -> {level} | Temp: {currentTemp:.2f} °C | Mark: {markTemp:.2f} °C")

         # Periodic temperature print
         now = time()
         if now - _last_print >= PRINT_INTERVAL:
               if markTemp is None:
                  markTemp = currentTemp
               print(f"Temp: {currentTemp:.2f} °C | Mark: {markTemp:.2f} °C | Level: {level}")
               _last_print = now

         # Auto adjust level based on ±5°C
         if markTemp is None:
               markTemp = currentTemp

         if level != 0:
               diff = currentTemp - markTemp
               if diff <= -5:
                  level = max(0, level - 1)
                  markTemp = currentTemp
                  print(f"[Auto] Temp down -> Level {level} (Temp: {currentTemp:.2f} °C)")
               elif diff >= 5:
                  level = min(4, level + 1)
                  markTemp = currentTemp
                  print(f"[Auto] Temp up   -> Level {level} (Temp: {currentTemp:.2f} °C)")

         level = motor_run(level)
         sleep(0.5)

   try:
      main()
   except KeyboardInterrupt:
      print("\nExiting...")
   finally:
      motor.stop()
      sleep(0.1)

**Comprendre le code**

1. **Initialisation NeoPixel**

   - Le script utilise SPI pour controler un anneau/bandeau de LEDs NeoPixel (``LED_COUNT = 12``).
   - ``auto_write=False`` est active pour que les LEDs se mettent a jour uniquement lorsque ``strip.show()`` est appele, ce qui evite le scintillement et ameliore les performances.
   - Les LEDs sont effacees au demarrage en utilisant ``strip.fill(0)`` et ``strip.show()``.

2. **Configuration materielle de l'encodeur rotatif**

   - Trois broches GPIO sont utilisees :
     - ``CLK_PIN`` et ``DT_PIN`` fournissent les signaux en quadrature pour la direction et les pas de rotation.
     - ``SW_PIN`` est l'entree du bouton de l'encodeur.
   - Toutes les broches utilisent des resistances de tirage internes (``Pull.UP``), et le bouton est **actif a LOW** (presse = ``0``).

3. **Parametres cles (reglage du comportement)**

   - ``DETENTS_PER_CYCLE`` definit le nombre de “clics” physiques necessaires pour effectuer une rotation complete de la teinte (0–360°).
     - Une valeur plus grande donne un controle plus fin des couleurs.
   - ``TRANSITIONS_PER_DETENT`` convertit les transitions brutes en quadrature en “un cran = un comptage”.
     - De nombreux encodeurs produisent 2 transitions par cran, mais certains en produisent 4. Ajuster cette valeur ameliore la precision.

4. ``hue_to_rgb()``

   - Convertit une valeur de teinte dans la plage ``0.0 ~ 1.0`` en un tuple RVB ``(R, G, B)`` avec des valeurs ``0 ~ 255``.
   - Cela permet de generer facilement des changements de couleur fluides en utilisant le modele de couleur HSV.

5. ``apply_color_from_detent()``

   - Mappe le compte de crans de l'encodeur a un index de teinte en utilisant le modulo :
     - ``hue_idx = detent % DETENTS_PER_CYCLE``
   - Convertit la teinte en couleur RVB et met a jour toutes les LEDs avec ``strip.fill(color)`` suivi de ``strip.show()``.
   - Utilise ``last_hue_idx`` pour eviter de rafraichir les LEDs lorsque la teinte calculee ne change pas, ce qui reduit les mises a jour inutiles.
   - Affiche l'angle de teinte actuel, la valeur du cran et la couleur RVB pour le debogage/feedback.

6. ``reset_all()``

   - Reinitialise l'etat du compteur interne :
     - ``raw`` (nombre de transitions brutes)
     - ``last_detent`` (dernier cran affiche)
     - ``last_hue_idx`` (dernier index de teinte affiche)
   - Appelle ``apply_color_from_detent(0)`` pour restaurer immediatement les LEDs a la couleur de depart (Teinte = 0°).

7. **Boucle principale (interrogation + detection de direction)**

   - Le programme interroge ``CLK`` en continu et verifie les changements :
     - Si ``CLK`` change, l'encodeur a avance d'un pas dans la sequence en quadrature.
   - La direction est determinee en comparant DT a CLK :
     - ``dt.value() != c`` signifie une direction de rotation (incrementation)
     - sinon decrementation
   - Le nombre de transitions brutes est converti en crans :
     - ``detent = raw // TRANSITIONS_PER_DETENT``
   - La couleur des LEDs est mise a jour uniquement lorsque la valeur du cran change.

8. **Reinitialisation du bouton et anti-rebond**

   - Lorsque le bouton est presse (``sw.value() == 0``), le programme appelle ``reset_all()``.
   - Un court delai anti-rebond est applique et le script attend que le bouton soit relache pour empecher plusieurs reinitialisations a partir d'une seule pression.

9. **Sortie propre**

   - Appuyer sur ``Ctrl + C`` quitte le programme.
   - Dans le bloc ``finally``, toutes les LEDs sont eteintes (``strip.fill(0)`` et ``strip.show()``) pour laisser le materiel dans un etat sûr.

**Depannage**
-------------------

- **Les LEDs ne s'allument pas**

  - Verifiez le cablage du module LED WS2812.
  - Assurez-vous que l'interface NeoPixel SPI du Fusion HAT+ est activee.
  - Assurez-vous d'utiliser un module LED WS2812/WS2812B supporte.

- **Les couleurs changent trop vite ou trop lentement**

  - Ajustez ``STEPS_PER_CYCLE`` pour affiner ou augmenter la sensibilite.

- **L'appui sur le bouton ne reinitialise pas la teinte**

  - Verifiez que SW est connecte a la GPIO27.
  - Assurez-vous que la broche est configuree avec ``pull=Pin.PULL_UP``.

- **Le script se termine immediatement**

  - Confirmez que ``pause()`` est importee depuis ``signal``.
  - Assurez-vous qu'aucun autre processus n'utilise le SPI.


**Essayez par vous-meme**
-------------------

Vous voulez etendre ce projet davantage ? Essayez ces idees :

1. **Ajouter le controle de luminosite**

   Utilisez une autre variable (par exemple, pression de l'encodeur + rotation) pour regler la luminosite des LEDs de 0 a 255.

2. **Ajouter plusieurs modes d'affichage**

   Appuyez sur l'encodeur pour parcourir les modes :

   - Couleur unie (par defaut)
   - Animation arc-en-ciel
   - Effet de respiration
   - Balayage de couleur

3. **Ajouter une bascule d'alimentation**

   Appuyez longuement sur le bouton de l'encodeur pour allumer/eteindre l'anneau de LEDs.

4. **Rendre le changement de teinte plus fluide**

   Augmentez ``STEPS_PER_CYCLE`` ou ajoutez une interpolation pour des transitions parfaitement lisses.

5. **Afficher le retour de direction**

   Faites briller une LED en vert lors d'une rotation horaire, en rouge lors d'une rotation antihoraire.

Ces petites extensions transforment le simple “Potard de teinte” en une interface de controle RVB polyvalente.
